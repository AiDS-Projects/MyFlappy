# PRD — 建立难度参数配置常量表

> 所属需求：核心玩法：难度递增曲线

## 用户故事
作为游戏策划/开发者，我希望将 MyFlappy 所有难度相关参数（管道移动速度、管道上下开口间距、管道生成间隔）集中到一个统一的配置常量表中，每个参数都明确定义初始值、随得分的变化速率、上限/下限，从而让后续「难度曲线计算」逻辑直接引用该配置，避免魔法数字散落在各游戏脚本中，便于快速调整平衡。

## 功能需求
1. 建立统一难度配置常量表（如 difficultyConfig），集中存放管道速度、开口间距、生成间隔三个维度的参数。\n2. 每个难度参数采用统一结构定义：初始值(initial)、随得分变化速率(perScore)、下限(min)、上限(max)。\n3. 提供 TypeScript 类型声明（DifficultyParam 接口），禁止使用 any，保证类型安全。\n4. 管道速度参数：初始值 160（px/s），每得 1 分增加 2，上限 280（px/s）。\n5. 开口间距参数：初始值 170（px），每得 1 分缩小 1，下限 110（px）。\n6. 管道生成间隔参数：初始值 1.6（秒），每得 1 分缩短 0.01，下限 0.9（秒）。\n7. 配置以常量形式导出，供游戏主循环、管道生成逻辑、碰撞与分数计算模块统一 import 引用。\n8. 参数数值可通过单一入口修改，修改后无需改动游戏逻辑代码即可完成调平衡。

## 验收标准
1. 难度配置常量表包含且仅包含 3 个难度参数（管道速度、开口间距、生成间隔），每个参数均具备 initial、perScore、min、max 四个字段。\n2. 每个参数满足约束：min ≤ initial ≤ max，且 perScore 为有限数值（非 NaN/Infinity）。\n3. 管道速度参数满足：initial=160、max=280，且 max > initial（保证随得分递增有上升空间）。\n4. 开口间距参数满足：initial=170、min=110，且 min < initial（保证随得分缩小有下限）。\n5. 生成间隔参数满足：initial=1.6、min=0.9，且 min < initial。\n6. 游戏逻辑代码（移动、生成、碰撞、计分）中不出现任何硬编码的难度魔法数字，全部引用配置常量；通过代码检索可验证无游离数值。\n7. 配置类型通过 TypeScript 编译检查，DifficultyParam 接口字段类型均为 number，项目编译 0 报错。\n8. 修改配置表中任一参数的数值后，无需改动游戏逻辑代码即可生效（仅需重新编译/加载）。

## 边界条件（不做的事）
1. 不实现难度曲线计算逻辑本身（速度/间距/间隔随得分如何变化、何时触发），仅建立供其引用的配置常量表。\n2. 不新增障碍物类型（移动管道、旋转门）与道具（护盾、慢速）。\n3. 不实现难度相关 UI 展示（如当前难度等级、速度指示条）。\n4. 不包含死亡重开难度重置逻辑。\n5. 暂不引入外部配置文件/远程配置系统，仅使用代码内常量表。
